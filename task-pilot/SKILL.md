# Antigravity Task Pilot (AT-Pilot) 技能指南

此技能允许 Agent (您自己) 协助用户在 Antigravity 聊天窗口中跟踪多类型并行任务的进度。任务支持休眠周期，在休眠期过后进入“待确认”状态，由您提示用户确认并更新进度，最终生成日报。

所有数据都安全地保存在本地的 `tasks.json` 数据库中。

## 核心指令映射

当用户表达以下意图时，您必须在后台使用 `run_command` 执行对应的 `tasks-cli.js` 脚本指令，并向用户展示美观的 Markdown 返回结果。

### 1. 新增任务 (录入任务)
*   **用户意图**: "帮我记一个任务..."，"新增任务..."
*   **执行命令**: `node /Users/tony/.gemini/config/skills/task-pilot/tasks-cli.js add --desc "<任务描述>" --type "<任务类型>" --deadline "<截止时间>" --goal "<当前目标>" --sleep "<休眠周期>" --resources "<资源1,资源2>"`
*   **参数映射**:
    *   `--desc` / `-d`: 任务描述
    *   `--type` / `-t`: 任务类型（例如：开发、文档、研究、会议等，默认：其他）
    *   `--deadline` / `-dl`: 截止时间（例如：今天下班前、明天、2026-07-05等）
    *   `--goal` / `-g`: 当前具体目标（小步骤）
    *   `--resources` / `-r`: 任务关联的各种资源/链接（如 Jira 链接、GitLab MR 链接、飞书文档等，用英文逗号分隔）
    *   `--sleep` / `-s`: 休眠周期。支持格式如：`10s` (10秒)、`30m` (30分钟)、`2h` (2小时)、`1d` (1天)。休眠期内该任务在 pending 列表中隐藏。
*   **提示**: 务必在调用前向用户确认或根据上下文推断必需参数。如果用户没给休眠周期，默认可以是 `0s`（即立即可见）或引导用户设置合理的检查周期。

### 2. 检查待确认的任务 (已唤醒任务)
*   **用户意图**: "有哪些待确认的任务？"，"有什么任务醒了？"，"检查进度"
*   **执行命令**: `node /Users/tony/.gemini/config/skills/task-pilot/tasks-cli.js list-pending`
*   **返回处理**:
    *   如果列表为空，友好告知用户所有任务当前均在休眠中。
    *   如果列表有任务，逐一展示并引导用户进行二次确认：“ID为 **T1** 的任务已经到达检查时间，当前目标是 [当前目标]，请问目前进度是多少，下一个目标是什么？”

### 3. 查看所有任务 (全局视图)
*   **用户意图**: "列出所有任务"，"我有哪些任务？"，"任务列表"
*   **执行命令**: `node /Users/tony/.gemini/config/skills/task-pilot/tasks-cli.js list-all`
*   **返回处理**: 直接打印输出的 Markdown 状态表格。

### 4. 二次确认进度 (更新进度 & 重新休眠)
*   **用户意图**: "T1 进度 50%，下一个目标是..."，"T2 已经做了一半，下午再提醒我"
*   **执行命令**: `node /Users/tony/.gemini/config/skills/task-pilot/tasks-cli.js confirm --id "<ID>" --progress "<0-100>" --goal "<新目标>" --sleep "<新休眠周期>" --resources "<新资源1,新资源2>"`
*   **参数映射**:
    *   `--id`: 任务短 ID (如 T1, T2)
    *   `--progress`: 最新进度数字 (0-100)
    *   `--goal`: 下一阶段的具体子目标
    *   `--resources`: 更新/重置关联的资源链接（用英文逗号分隔）
    *   `--sleep`: 重新进入休眠的周期 (如 `2h`、`1d` 等)

### 5. 标记任务已完成
*   **用户意图**: "完成 T1"，"T2 做完了，总结为..."
*   **执行命令**: `node /Users/tony/.gemini/config/skills/task-pilot/tasks-cli.js complete --id "<ID>" --summary "<工作量总结>"`
*   **参数映射**:
    *   `--id`: 任务短 ID
    *   `--summary`: 对该任务所做工作的具体描述（这是日报的关键数据源，请引导用户给出详细的产出，例如：“完成了接口联调，修复了2个Bug，测试全部通过”）。

### 6. 生成日报数据源
*   **用户意图**: "生成今日日报"，"今天的日报"，"日报汇总"
*   **执行命令**: `node /Users/tony/.gemini/config/skills/task-pilot/tasks-cli.js report [--date "YYYY-MM-DD"]`
*   **返回处理**: 打印生成的 Markdown 格式日报。告知用户可以直接复制使用。

## 自动监控与定时唤醒机制
为了实现任务进度的自动监控，您（Agent）应当主动在后台利用系统的 `schedule` 定时器工具跟踪任务唤醒时间：
1.  **查询下一唤醒点**：在用户确认/新增任务导致任务休眠时间变更后，或者在每个交互轮次结束时，通过读取 `tasks.json`（或使用 `list-all`）找出当前所有活跃任务中 **最接近当前时间且大于当前时间** 的 `sleep_until` 时间戳。
2.  **设定定时器**：计算该时间戳与当前时间的差值（秒数），并调用 `schedule` 工具设定 one-shot 定时器：
    *   `DurationSeconds`: 差值秒数
    *   `Prompt`: `"⏰ 定时提醒：任务已过休眠期，请执行 list-pending 并汇总当前待确认的任务进度给用户。"`
    *   `TimerCondition`: `never`
3.  **汇总唤醒**：当定时器触发并向您发送唤醒消息后，您必须执行 `list-pending` 查询，并自动将所有已到期需要二次确认的任务汇总展示给用户。

## 交互原则
1.  **主动检索**：每次用户在新的一天或隔了较长时间后发送首条消息时，或者主动要求时，首先悄悄执行 `list-pending` 检查是否有唤醒的任务。
2.  **清晰引导**：引导用户在完成一个小目标后，通过 `confirm` 将进度推前，并输入新的休眠时间。例如：“该任务已确认更新。请问需要将其休眠多久（例如 2h, 4h, 1d）再提醒您确认下阶段进度？”
3.  **日报归档**：在标记任务完成时，务必提醒用户该记录将被计入日报数据源，确保 `summary` 信息足够具体、专业。
